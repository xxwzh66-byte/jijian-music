# V1.3.0 — 一千二百首歌，没有一首想听

`versionCode = 15` · 可从 1.2.0 直接覆盖安装

V1.1.6 给曲库配了专辑页，V1.2 让浏览变便宜。两件都做完了，曲库大起来仍然没人
回答那个真正的问题：**今晚听什么**。一千二百首按标题排序的列表不是答案。

## 四张没人维护的架子

首页多了一条横滑带「为你挑的」，里面是四张从曲库加播放记录现算的架子：

- **最近添加** — 近 30 天入库，按入库时间倒序
- **最常播放** — 按播放次数排，次数相同比最近一次
- **从未播放** — 库里还没轮到的
- **很久没听** — 播过，但超过 90 天没再播

各三十首，顺序固定，空了就自己消失。它们不是歌单：不落盘、不能改名、不能编辑。

三个判断值得说明：

- `dateAdded = 0` 是「不知道」，不是 1970。信它会让从旧版本升级上来的用户第一次
  打开就看到整库躺在「最近添加」里——一张装着所有东西的架子不是架子。
- 「从未播放」在有第一条播放记录之前保持为空。全新安装时每首都没播过，这架就等于
  整库，而那正是用户已经看得见的东西。
- 「很久没听」要求播过才算。没播过不是被遗忘，是还没轮到。

点一张架子，队列就是那三十首，不续到全库——点「最常播放」就是要那三十首，让队列
一首之后继续滑进曲库剩下的部分，架子在一首歌之后就失去意义了。

## 一次搜索，五种答案

首页工具栏那个输入框以前只过滤它下面的列表：输入歌单名什么也搜不到，输入专辑名能
搜到里面的歌却搜不到这张专辑。

顶栏新增的搜索按钮打开搜索页，一次查询返回五段：**歌曲 / 收藏 / 专辑 / 歌手 / 歌单**。
两条规则让它保持诚实：

- 匹配只在一处实现。命中判定交给 V1.2 那份预先小写的 `LocalIndex`，搜索页直接拿
  已经过滤好的曲目。再匹配一遍就是第二份「什么算命中」的实现，迟早漂移。
- 专辑与歌手从**匹配后的曲目**分组。用户问的是「我哪些专辑里有它」，不是「把我的
  专辑列出来」。

已经出现在歌曲段里的收藏会从收藏段剔掉——同一首歌在一页上出现两次，读起来像 bug。
专辑、歌手、歌单各封顶六条。

从搜索结果点进专辑，专辑页会盖在搜索页上面；返回则回到搜索结果，关键词还在。
