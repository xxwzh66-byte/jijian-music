## 三条产品决定

### 一、应用内更新只认 debug 包

「下载并安装」有一条隐含前提：下载的包必须和用户手里那份同一个签名。V1.1.7 上线
时的选择是优先挑不带 `debug` 的资产（release 包），V1.4.5 反过来——优先挑
`-debug.apk`。

这样做的好处是自动安装这条主路径必成功（debug 包能覆盖 debug 包），只维护一种签名，
崩溃栈还带行号。`UpdateChecker.parseRelease` 仍保留 `?: candidates.firstOrNull()`
的退路：1.4.5 之前的 Release 只有正式包，那些版本还得能被识别成「有更新」。

### 二、删掉「启动时自动检查更新」开关与 24h 节流

两个都想省网络请求的机制合起来，产出一个只在第一次启动有效的功能：开关默认开着，
但 `lastUpdateCheckAt` 让第二次启动起就静默跳过。

现在 `UpdateStore.checkOnStartup()` 只保留「状态不是 IDLE 就别重入」这一个守卫，
每次进应用都查一次。失败与「已是最新」仍旧退回 IDLE，不往设置页塞用户没要的状态。

`lastUpdateCheckAt` 字段留着——备份文件里有它，删了旧备份读不回。

### 三、设置页新增「项目地址」

「更新」分区「版本」下面多一行，点一下直接用系统浏览器打开仓库：

```
https://github.com/xxwzh66-byte/jijian-music
```

## 两个真 bug

### 一、随机播放：第一次启动直接卡死

三样东西叠成环，缺一个都不至于死：

| 环节 | 做了什么 | 为什么致命 |
| --- | --- | --- |
| `QueueMirror.resync` | 每次队列变更都写 `shuffleModeEnabled` | 这个属性会走 `updatePlaybackInfo` → `onTimelineChanged` → 再装一次 order |
| `onQueueMutated` | 同一处又调 `resetShuffle()` | 上面那条之外独立再装一次 |
| `resetShuffle` | `shuffleState.invalidate()` | generation 一变 memo 守卫失效，**必然**再装 |
| `installShuffleOrder` | `setShuffleOrder` → `createMaskingTimeline()` | 每装一次造一条新 timeline，跨进程 `MediaController` 把每轮放大成主线程停顿 |

冷启动时 `prepareRestored`（队列缩到 1 首）→ 等首次扫描 → `backfillQueue`（队列
膨胀到整库）→ `resetShuffle`，正好把上面四条串在同一帧里。

三处改动：

```kotlin
// QueueMirror：repeat 归我，shuffle 归 installShuffleOrder
private fun resync(t: MirrorTarget) {
    t.repeatMode = repeatFlag()
    onQueueMutated()
}

// PlayerController：队列变了只让已装的 order 作废，不作废账本
private fun resetShuffle() {
    forgetInstalledOrder()
    installShuffleOrder()
}

// PlayerController：装 order 加熔断，1 秒最多 4 次
if (++installWindowCount > MAX_INSTALLS_PER_WINDOW) {
    Log.e(TAG, "shuffle order install throttled: $installWindowCount in ${INSTALL_WINDOW_MS}ms")
    return false
}
```

队列长短变化时，账本里那些旧下标已经被 `ShuffleMemo.slot` 的 `cached in 0 until size`
挡掉了，不需要整本作废。真正该「重新随机」的只有 `toggleShuffle`——用户按开关那
一下仍然 `invalidate()`。

### 二、切换样式一次性加载多次样式

`Crossfade` 的定义就是交叉溶解：过渡期**同时组合两套舞台**。两套各自带一张封面、
一个 Canvas（唱片那套还有 30–50 圈凹槽循环）、一套手势，看起来就是「切一次、加载
好几次」。

改成顺序切换：

```kotlin
val stageAlpha = remember { Animatable(1f) }
var shown by remember { mutableStateOf(skin) }
LaunchedEffect(skin) {
    if (skin == shown) return@LaunchedEffect
    stageAlpha.animateTo(0f, tween(FADE_OUT_MS, easing = LinearEasing))  // 90ms
    shown = skin
    stageAlpha.animateTo(1f, tween(FADE_IN_MS, easing = LinearEasing))   // 150ms
}
```

任一时刻只有一套舞台存在。总时长 240ms 比原来的 200ms 略长，但只有 `shown` 换掉那
一帧同时存在两套。顺手把 `pointerInput(sk)` 改成 `pointerInput(Unit)`——水平拖动是
容器的手势，和里面画什么无关。
