# 极简music V1.4.2 — 随机播放不再挑不起

`versionCode = 18` · `versionName = "1.4.2"`

这一版只动一处：随机播放抽下一首的那个函数。没有新功能，没有界面变化。

## 修掉的崩溃

`RandomShuffle.pickOther` 原来这样算候选数组：

```kotlin
val candidates = IntArray(size - exclude.count { it in 0 until size })
```

`exclude` 是「不许抽到的下标」。绝大多数时候它装一个数（当前曲），按「上一首」时
装两个（当前曲 + 刚播完那首）。但只要这两个数**相同**，上面这个减法就错了。

什么时候会相同：队列被你拖动排序、或者删掉一首之后，`lastTrack` 还指着旧位置，
而 `current` 已经落到同一个格子上。这时：

- 两首的队列：`2 - 2 = 0`，候选数组空了，退回「抽到谁算谁」——不崩，但排除失效；
- 更旧的队列 / 更复杂的编辑：`size - 2` 直接是负数，`IntArray(负数)` 抛
  `NegativeArraySizeException`，抛在 ExoPlayer 的播放线程上。

新的实现只剩一个判定：

```kotlin
private fun banned(value: Int, exclude: IntArray, size: Int): Boolean {
    if (value !in 0 until size) return false
    for (v in exclude) if (v == value) return true
    return false
}
```

越界下标不算禁用（队列缩短后残留的旧下标不该白占一个槽），重复下标天然无害。
调用方不再需要保证 `exclude` 干净。

## 明确不做「近期去重」

做这一版之前先确认了一件事：要不要顺手加一条「最近 N 首不许重复」的窗口。

答案是不加。一条窗口规则看起来是改进——同一首歌不会连着出现——实际代价是
「随机」变成「轮转的近亲」：队列 N 首、窗口 M 首，下一首只可能在剩下 `N-1-M`
首里选，小队列上直接等于顺序播放。更麻烦的是它不可见，界面上没有任何地方写
「最近 30 首不会重复」，用户只能自己猜为什么某首歌点不出来。

随机播放允许同一首歌在几步之内再次出现。这条写进了 KDoc，也写了测试
`anIndexThatJustPlayedIsStillReachable` 钉住。

## 测试

412 → **415 项 / 41 个类 / 0 失败**。新增 3 项都在 `RandomShuffleTest`：

| 用例 | 守的是什么 |
|---|---|
| `duplicateExclusionsDoNotBlowUpTheCandidateSize` | 同一个下标传两遍不得把候选数算成负数 |
| `anIndexThatJustPlayedIsStillReachable` | 刚播过的下标仍然抽得到（钉住「无窗口」） |
| `outOfRangeExclusionsAreIgnoredRatherThanReserved` | 越界下标不占槽位 |
