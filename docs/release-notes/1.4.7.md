# 极简music 1.4.7

**versionCode = 22** · 只发 debug 包 · 可从 1.4.6 覆盖安装

---

## 一个从 V1.0.1 起就没生效过的规则

「上一首」不是简单地把「下一首」倒过来放——用户要的是**也随机**。为了不让它
随机到刚刚才听过的那一首（那就等于把刚才按的那一步撤销了），`previousIndex`
里有一条避开规则，注释写着「避开刚播完的那首」。

它一次都没生效过。

依据是 `ShuffleMemo.lastTrack`，而 `lastTrack` 由 `started(size, current)` 写
入 —— 写进去的正是**刚开播的这一首**，也就是调用方马上要传进来的 `current`。
于是避开规则的前置条件：

```kotlin
if (size > 2 && justPlayed in 0 until size && justPlayed != current)
```

第三个条件恒为假，整个分支永远走 `else`，`avoid` 里永远只有 `current` 自己。

用户能看到的是两件事：

- 播放 3 → 按「下一首」到 5 → 按「上一首」，有 1/7 的概率原样退回 3。看起来
  像按键没生效，只好再按一次。
- 连按两次「上一首」可以在同一对曲子之间来回弹。

## 修法

`ShuffleMemo` 新增 `cameFrom`：**我们从哪一首走到现在这一首的**。

```kotlin
fun started(size: Int, current: Int) {
    if (current != lastTrack && lastTrack in 0 until size) {
        cameFrom = lastTrack
    }
    lastTrack = current
    next.clear()
    previous.clear()
}
```

两个细节是必须的：

1. **在覆盖 `lastTrack` 之前转存**。晚一行，旧值就没了。
2. **重复上报同一首不覆盖 `cameFrom`**。换歌有两条路径都会上报 —— media3 的
   `onMediaItemTransition`（通知栏、蓝牙、自动续播）和 `PlayerController` 的
   `playIndex`（app 内按键）。第二条如果不判等就写，`cameFrom` 会变成当前首，
   避开规则又白写了。

`previousIndex` 的避开依据从 `lastTrack` 换成 `cameFrom`，其余不变：仍然是
`size > 2` 才启用（两首队列没有第三个位置可去，排除两个就等于无解），仍然均
匀抽。

## 测试

新增 `RandomShuffleBacktrackTest`，4 个用例。最关键的一条是
`previousDoesNotUndoTheNextPressThatJustHappened`：50 个种子下从 3 走到随机
目标、再问「上一首」，断言退回 3 的次数**严格为 0**。

这条断言的第一版写成了 `assertNotEquals(50, undone)` —— 那等于什么都没说，
改实现前后都会通过。严格化之后它立刻暴露了本文开头的缺陷（50 个种子里若干
次退回），修完才转绿。

同批把 V1.4.6 留下的 `forgetDrawsKeepsTheTrackThatJustPlayedSoPreviousStillAvoidsIt`
改成 `forgetDrawsKeepsTheTrackWeCameFromSoPreviousStillAvoidsIt`：它原本断言的
就是那个错误语义（`lastTrack` 作依据），继续留着会把 bug 锁死在测试里。

**426 项单元测试 / 42 个类 / 0 失败。**

## 没做的

- 不做近期去重窗口（V1.4.2 用户两轮追问后明确否决）。
- 不做洗牌袋、不做歌手/专辑分散、不做加权、不持久化种子。
- `RandomShuffleOrder.getFirstIndex()/getLastIndex()` 仍返回固定端点
  `0` / `size - 1`。理论上 `repeatMode = ALL` 回绕时通知栏会跳到队列第一首，
  但那要求先走到「没有下一首」的位置，而随机模式下每一步都抽得到下一首 ——
  够不到，这一版不动。
