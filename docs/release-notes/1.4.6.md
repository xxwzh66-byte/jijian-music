# V1.4.6 · 那张 order 一直是活的，所以一次都不该重装

`versionCode = 21` · `applicationId = com.lxmusic.android.debug`

## 一句话

随机播放剩下的 bug 不是「抽得不对」，是**重装 order 这件事根本不该发生**——
装进 ExoPlayer 的那份 order 是活视图，重装恒等于零收益，而重装正是那个让通知栏
和 app 各随机各的环。

## 这次错的是一层理解

`RandomShuffleOrder` 的八个方法全部转发到同一个 `RandomShuffleState`，而它的
抽样账本 `ShuffleMemo` 在 `copy()` 里是**共享**的（V1.4.3 就改成了这样）。所以
不管 media3 克隆多少份，它们看的都是同一本账 —— 队列换序、账本作废、generation
前进，下一次被问就给出新答案。

既然是活的，重装就恒等于零收益。而重装恰恰是那个环：

```
setShuffleOrder
  → createMaskingTimeline()
  → PlaylistTimeline 没有重写 equals
  → Timeline.equals 恒 false
  → onTimelineChanged
  → 回到 installShuffleOrder
```

V6.1 用 generation 做 memo 守卫，把无限环截成「一次开关多付一轮」；V1.4.5 又
加了一层 1 秒 4 次的时间窗熔断去兜「多轮」。两层都是在给一个不该存在的循环
装闸门，而闸门本身有代价。

## 两个真缺口

### 1. 熔断那条 return 把模式也吞了

```kotlin
if (++installWindowCount > MAX_INSTALLS_PER_WINDOW) {
    Log.e(TAG, "shuffle order install throttled: ...")
    return false          // ← 在 shuffleModeEnabled 被写下去之前就返回了
}
```

这一轮里 ExoPlayer 根本不知道随机开着，于是通知栏 / 锁屏 / 蓝牙按它自带的
`ShuffleOrder` 走，app 内按键按我们的走。两边各随机各的 —— 这是最难复现、
也最难解释的一类「随机播放的 bug」。

现在三条退出路径（熔断 / memo 命中 / 正常装完）统一走 `syncShuffleMode()`。

### 2. 账本是按下标记的，队列一变就指错歌

V1.4.5 为了掐断上面那个环，把 `resetShuffle()` 里的 `shuffleState.invalidate()`
删了 —— 队列变了也不作废账本。留下一个真缺陷：队列增删或移动之后，同一个下标
已经是另一首歌，旧答案虽然仍在 `0 until size` 范围内合法，却指向一首这一次
没被抽中的曲子。表现是「随机老是走那几条路」。

修法是 `ShuffleMemo.forgetDraws()`：扔答案、**留 `lastTrack`**、**不动
generation**。三件事缺一不可。

## 测试

**422 项 / 41 个类 / 0 失败**（V1.4.5 是 417）。新增 5 个用例全压在
`RandomShuffleStateStalenessTest`：

- `forgetDrawsDiscardsTheAnswersTheQueueEditInvalidated`
- `forgetDrawsKeepsTheTrackThatJustPlayedSoPreviousStillAvoidsIt`
- `forgetDrawsLeavesTheGenerationAloneSoNoOrderGetsReinstalled`
- `invalidateStillBumpsTheGenerationAndForgetsTheLastTrack`
- `aForgottenLedgerDrawsAgainInsteadOfReplayingTheOldPath`

## 没有验证到的部分

本机没有可用模拟器或真机（WHPX 初始化后 qemu 静默退出），所以改动的运行时行为
**没有被端到端验证过**。验证只到「JVM 单测 + dex/APK 静态核验」。

如果实机上仍能复现，抓 `PlayerController` 标签的 logcat：正常路径现在除了
`shuffle order deferred`（playlist 编辑还在路上，属预期）与
`shuffle order refused`（ExoPlayer 拒收，属异常）之外，不该再出现任何一行。

## 仍然不做

洗牌袋、近期去重窗口、歌手/专辑分散、加权抽样、种子持久化、段式洗牌 —— 与
V1.4.2 的决定一致。
