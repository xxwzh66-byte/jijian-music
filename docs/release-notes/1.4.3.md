## 两个问题

### 一、开关随机播放后，下一首必然是同一首歌

根因是两个缺陷叠在一起。

**单槽位缓存。** 抽样缓存原本只有 `nextPick` / `previousPick` 两个整数。但一次换歌
里 media3 会用不同的 `current` 问好几遍——通知栏要播放中曲目的下一首、
`MediaPeriodQueue` 要预览后面几首、自动续播再问一次——后一个答案把前一个覆盖掉。

**副本拿到的是快照。** `copy()` 原本逐个字段抄给克隆体。而 `MediaSourceList` 会用
`cloneAndClear().cloneAndInsert(...)` 修长度不匹配，**装进 ExoPlayer、替通知栏作答的
正是那份克隆体**；`onTrackStarted` 只在 `PlayerController` 里对父实例调用，克隆体
永远收不到。父实例每次换歌清账重抽，克隆体却一直端着换歌前抽的下标。

修法：缓存换成按 `current` 分槽的 `ShuffleMemo`，副本**共享**同一个账本。

### 二、播放页切样式卡顿

三处都是「在 composition 里读动画值」，每帧重组整棵子树：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 唱片 | `.rotate(rotation.value)` | `.graphicsLayer { rotationZ = ... }` |
| 唱臂 | `drop: Float` | `drop: () -> Float`，Canvas 内求值 |
| 歌词行 | 动画 `fontSize` / `lineHeight` | 动画缩放，字号固定 |
| 切台 | Crossfade 300ms | `tween(200)` |

唱片子树里有一次 30–50 圈的凹槽 `drawCircle` 循环加一张封面，60fps 下等于每秒
重建 60 次。字号是布局属性，动画它等于每帧重新排版一行字。
