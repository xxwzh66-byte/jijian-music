# V1.4.0 — 那些读屏从来没被告知的事

`versionCode = 16` · 可从 1.3.0 直接覆盖安装

三件事，全部关于「能不能用」，而不是「看起来怎样」。

## 歌词行第一次真的是个控件

`LyricView` 有一个 `onSeekTo: ((Long) -> Unit)? = null` 参数，从 V5 就在；两个调用点
（唱片版、歌词版）都老老实实传了 `onSeek` 进去。但函数体从头到尾没有调用过它。

也就是说：点歌词跳转——定时歌词在触摸屏上唯一的用处——被静默地废了八个版本。
没有任何测试或崩溃暴露它，因为「点了没反应」看起来就像「这里本来就不能点」。

现在一行歌词就是一个触摸目标，点哪一段都跳到那句自己的时间戳；翻译行和原文行共享
时间戳，所以点翻译不会跳到别处。6dp 的纵向补白让四五个字的短行也过 48dp 下限。
只有传了回调才可点，旧的只读用法行为不变。

读屏念的是「跳到这里播放 1:05，雨还没停」——歌词本身是半句话，半句话没有动词，
会被当成文本而不是按钮。

## 歌词就地调，不用走去设置页

字号和偏移以前只有设置页能改。但真想调的那一刻是**正在听某首歌、觉得某一行早了
半拍**的时候；走进设置页翻两个滑块再退回来，那一句已经过去了。

播放页右上角的菜单里现在有加减按钮，±5% 与 ±50ms 一档，落盘立刻生效。区间与设置页
那两个滑块**逐位相同**（0.7×–1.6×、±500ms）——不一致的后果很具体：在播放页按到
1.65×，回到设置页滑块会显示一个它自己永远拖不到的位置。

## 平板右栏不再固定 45%

以前宽屏就是「左 55% 列表 / 右 45% 播放页」，专辑页是全屏幕布盖在上面。在平板上打开
一张专辑，列表整片消失，退出来还得重新找位置。

现在右栏按优先级分配：**播放页 > 专辑页 > 空**。播放页优先是因为它是用户刚点出来的；
关掉播放页会回落到还开着的专辑页，而不是把右栏清空。没有曲目时播放页不占半屏——
一张空唱片加两个禁用按钮横在那里，不如把宽度还给列表。专辑页多分 5%（0.5 vs 0.45），
因为它是曲目表，5% 就是多一行。

## 一行一句话

原来一行曲目是「封面 + 标题 + 副标题 + 时长」四个节点，读屏要走四步，中途还会静默
跳过封面，而且从不说明这行能播。

现在一整行合并成一句话，动词随动作变：分组行说「打开」绝不说「播放」，迷你播放器说
「打开播放页」（点它是开播放页，不是开始播放）。读屏用户唯一能据以行动的信息就是
那个动词。

顺手修了一个从来没成立的承诺：所有顶栏的玻璃按钮注释都写着「42dp 触摸目标」，代码
却是 `padding` 写在 `size` 之前、`clickable` 写在 `padding` 之后——实际可点区域只有
38dp。现在外层是 48dp 的点击区，内层才是 38dp 的玻璃圆片。
